# openBD の調査記録

ISBNから書誌情報を取得する仕組みの取得元として openBD を調べた記録。
実装するときの「応答をどう変換するか」の仕様のもとにもする。

- 調べた日：2026-10-12
- 結論：書誌情報の取得元は openBD のみとする

## openBD とは

ISBNを指定すると、その本の書誌情報（書名・著者・出版社・出版日・価格・表紙画像など）を返すAPI。
株式会社カーリルと版元ドットコムによる openBD プロジェクトが提供している。

- ISBNで1冊ずつ（または複数のISBNをまとめて）取り出すAPIで、書名や著者名、キーワードでは検索できない
- 該当する本がなければ、その位置に `null` が返る
- 応答はJSON。書誌情報は出版業界の標準形式である ONIX の形で入っている

## 取得元を openBD にした理由

同じISBN（9784003101018『吾輩は猫である』岩波文庫）で、3つのAPIを呼んで比べた。

| 取得元 | 結果 |
|---|---|
| openBD | キーなしで取得できた。JSON |
| 国立国会図書館サーチ（OpenSearch） |openBD とほぼ同じ。 XML |
| Google Books | キーなしでは `429 RESOURCE_EXHAUSTED`（1日の上限が `0`）。APIキーが必要 |

- openBD は出版社が登録するデータを含むので、新刊が早く載り、表紙が付く本もある
- 国立国会図書館サーチは提供が続く見込みが高く、古い本に強い。openBD が使えなくなったときの移行先の候補になる
  - 個人で収益を得ない利用なら申請は不要。ただし継続して使う場合は、利用申請フォームで連絡先と利用内容を知らせるよう求められている
- 自分は新刊もよく買うため、載るのが早いopenBDを採用した。openBDで書誌情報を取得できなかった時に、予備で国立国会図書館サーチを呼び出せるような実装も考えられるが、優先度は低い機能と判断し、今回は見送った

## 利用条件と提供の状況

- 無料。APIキーや登録は不要
- データは本の紹介・販売促進のために使ってよい（個人・団体・企業を問わない）
- APIのデータを勝手に書き換えないこと
- 書誌情報や書影は変わったり消えたりする。キャッシュするなら早めに更新すること
- 提供状況は https://status.openbd.jp/ で確認できる
- 2023-07-25 に「openBD API（バージョン1）」の提供終了が発表された
  - JPRO（出版情報登録センター）から版元ドットコムへのデータ配信が、2023-06-05 に止まったため
  - 代替のAPIを「少なくとも60か月以上」提供するとされた。収録範囲と内容は変わるとされている
  - 2026-10-12 の時点では、`v1` のURLで応答が返っている

このアプリでの使い方（取得した値をフォームに入れ、利用者が確認・修正してから自分のDBに保存する。キャッシュはしない）は、上の条件の範囲に収まると判断した。

## 呼び出し方

```
GET https://api.openbd.jp/v1/get?isbn=9784003101018
GET https://api.openbd.jp/v1/get?isbn=9784873115658,9784798121963
```

- 応答は配列で、渡したISBNの順に1件ずつ入る。該当なしは `null`
- ISBNはハイフンなしのISBN-13で渡す（このアプリでは `app/isbn.py` の `normalize_isbn` でそろえてから渡す）

### このアプリでの呼び出し

画面からは `GET /api/isbn-lookup?isbn=<入力値>` を呼び、バックエンド（`app/routers/isbn_lookup.py`）が openBD を呼ぶ。取得した値はDBに保存しない。

- ISBNは1つずつ問い合わせる。タイムアウトは5秒で、リトライはしない
- 結果とステータス

  | 状況 | ステータス | `type` |
  |---|---|---|
  | 取得できた | 200 | |
  | ISBNがない・空・正しくない（openBD は呼ばない） | 422 | `missing` / `value_error` |
  | 該当なし（`null`） | 404 | `not_found` |
  | タイムアウト | 504 | `lookup_timeout` |
  | 接続できない、openBD がエラーを返した、応答がJSONでない、要素1つの配列でない、要素の形が想定と違う | 502 | `lookup_failed` |

- 502・504 の原因は画面には出さず、ログに警告として残す
- テストでは openBD をモックに差し替える。`tests/conftest.py` の `client` フィクスチャは、差し替えを忘れて本物の openBD を呼ぶとテストを失敗させる

## わかったこと

同じ項目でも、本によって値の書き方が違う（表記ゆれ）。今回は、1件（９９％の人が速くなる走り方）に違いがまとまって現れたが、件数が少なく、決まった組み合わせかは判断できない。これ以外の書き方が存在する場合に書誌情報が取得できない可能性はあるが、これ以上の調査は行わない。理由は、調査時間が膨大になることと、書誌情報が取得できなくても手動入力がアプリの機能としてあるため。

- **書名**：副題（` : …`）や巻（`. 上`、`巻1`）が付いた形で来る
- **著者**
  - 名前の書き方：`姓, 名, 生年-`（13件）と `姓 名`（1件）
  - 生没年（`1867-1916`、`1962-`）や、同名の人を区別する印（`pub.2011`）が付く
  - 姓と名がカンマで区切られている。このアプリは「複数の著者をカンマで区切る」ので、そのままでは使えない
  - `ContributorRole` は、その人が本にどう関わったか（著者・訳者・イラストなど）を表す ONIX のコード（コード表 List 17: Contributor role）。1人に複数の役割が付くことがあるので配列で入る
    - コードは「頭文字1文字＋数字2桁」で、頭文字がグループを表す。`A` は主な作者と作品そのものへの寄与、`B` は編集・改訂・翻訳、`C` は編纂、`D` は演出・制作、`E` は実演、`F` は撮影・録音、`Z` はその他
    - 例：`A01` 著者、`A12` イラスト、`A15` 序文、`A21` 解説、`B01` 編者、`B06` 訳者
    - `A` には序文・解説も含まれるので、頭文字だけでは著者かどうか決められない
  - `ContributorRole`：空の `[]`（13件）と `A01`（1件）
  - 役割が空の場合は、訳者も著者と区別できない（DDDは4名、アジャイルサムライは5名）。このため役割は使わない（「このアプリでの変換のしかた」の「著者」）
  - `summary.author`（例：`"Boswell,Dustin Foucher,Trevor 角,征典"`）は人と人の区切りがあいまいなので使わない。`DescriptiveDetail.Contributor` から組み立てる
- **出版社**
  - `summary.publisher` は全件に入っていた
  - `PublishingDetail` の中は、`Imprint` だけ（13件）と、`Imprint` と `Publisher` の両方（1件）
  - 出版元ではなく発売元が入ることがある（リーダブルコード：出版元はオライリー・ジャパンだが、発売元のオーム社が入っていた）
- **出版日**
  - `YYYYMM`（13件）と `YYYYMMDD`（1件）。フォームの例（`2024-05-10`、`2024-05`）とは形が違う
  - `PublishingDateRole`：`11`（13件）と `01`（1件）。コードの意味は調べていないので、値だけを記録する
- **価格**（`ProductSupply.SupplyDetail.Price[]`）
  - `PriceType` は価格の種類を表す ONIX のコード（コード表 List 58: Price type）

    | コード | 名称（原文） | 意味 |
    |---|---|---|
    | `01` | RRP excluding tax | 希望小売価格（税抜） |
    | `02` | RRP including tax | 希望小売価格（税込） |
    | `03` | Fixed retail price excluding tax | 法律で再販売価格が維持される商品の定価（税抜） |
    | `04` | Fixed retail price including tax | 同上の定価（税込） |

    - `03`・`04` は再販売価格維持が法律で適用される国で使う。日本の本は再販制度の対象なので、出版社が登録した定価は `03` で表すのが定義に合う
  - `PriceType` は `01`（13件）と `03`（1件）で、どちらも税抜。税込のコード（`02`・`04`）は1件もなかった。リーダブルコード 2400、DDD 5200 などは実際の本体価格と合う
  - コードと値の中身が食い違うことがある。岩波文庫は `01`（税抜）なのに値が `410 (税込)` だった。値に「税込」とあればそれを優先し、`PriceAmount` に数字以外の文字が付くことにも備える
  - 価格がない本もある（ぐりとぐら）
  - このアプリの `books.list_price` は定価（税込）なので、そのままでは入れられない
  - openBD・JPRO が `PriceType` の使い方を説明した公式の資料は見つからなかった。解釈は ONIX の定義と実際の値から判断した（openBD のAPI資料のPDFはほぼ画像で、価格の記述は読み取れなかった）
- **表紙**
  - `summary.cover`：空（13件）と URLあり（1件）
  - URL（`https://cover.openbd.jp/{ISBN}.jpg`）を開くと画像が返った

## このアプリでの変換のしかた

### 項目ごとの変換

| 項目 | 変換 |
|---|---|
| 書名 | `summary.title` をそのまま使う |
| 著者 | `DescriptiveDetail.Contributor` から組み立てる（下の「著者」） |
| 出版社 | `summary.publisher` |
| 出版日 | `summary.pubdate` を、`YYYYMMDD` → `YYYY-MM-DD`、`YYYYMM` → `YYYY-MM` にする。`YYYY` や、想定していない形（`1990.4` など）はそのまま |
| 定価 | `ProductSupply.SupplyDetail.Price` から求める（下の「定価」） |
| 表紙 | `summary.cover` が http/https のURLのときだけ使う |

- 取れなかった項目は空欄にする
- 文字数の上限（docs/db-design.md）を超えた値は切り詰めずに返し、保存のときの検証で利用者に気づいてもらう

### 著者

- `Contributor` に入っている人を全員入れる。訳者・解説者なども著者と一緒に並ぶ
  - `ContributorRole`（役割）は使わない。今回は14件中13件で空だったため、役割で絞り込める場面が少ない
  - 不要な人（訳者など）は、利用者がフォームで消す
- 名前の整え方
  - 生没年（`1867-1916`、`1962-`）や、同名の人を区別する印（`pub.2011`）を除く
  - 日本語の名前は姓と名をつなぐ：`夏目, 漱石` → `夏目漱石`、`平岩 時雄` → `平岩時雄`
  - 欧米の名前は名・姓の順にする：`Harari, Yuval N.` → `Yuval N. Harari`
- 複数の人はカンマで区切る

### 定価

`books.list_price` は定価（税込・円）なので、次のように求める。

1. `PriceType` が `02`・`04`（税込）のとき、または `PriceAmount` に「税込」とあるときは、その数字をそのまま使う
2. `PriceType` が `01`・`03`（税抜）のときは、×1.1 して端数を切り捨て、税込に換算する
   - 今の税率（10%）での定価になる。発売当時の税込価格とは違うことがある（例：消費税が5%だった時代の本）
   - `list_price` は参考の情報で、書籍費の集計には使わない（集計は `purchases.amount`）ので、この差は許容する
3. `PriceType` がない、または `01`〜`04` 以外で、`PriceAmount` にも「税込」とないときは、税込か税抜かわからないので空欄にする
4. 価格がない、または `PriceAmount` から数字を取り出せないときは空欄にする

- 通貨（`CurrencyCode`）が円（`JPY`）以外の価格は使わない。通貨がないときは円とみなす
- 価格が複数あるときは、上の 1〜2 で定価を求められる最初の価格を使う

### 編集画面で取得し直すとき

- 取得できた項目だけを上書きし、取れなかった項目は入力済みの値を残す
- 登録画面ではフォームが空なので、取得できた項目が入るだけになる
- 取得した値はフォームに入れるだけで、保存は利用者が送信したときに行う。手放した日（`disposed_on`）や読書記録・購入記録は変わらない（docs/db-design.md）
